# SAIRO — Silent End-to-End Encrypted Chat (MERN Stack)

A modern, soothing, zero-registration end-to-end encrypted chat application built with **MongoDB, Express, React, Node.js, and Socket.IO**.

No accounts, no emails, no real credentials. User A creates a room with a **secret passcode** and shares that passcode (or a passcode-locked room link). Any peer who enters that secret passcode unlocks and connects immediately—without anyone ever exposing real identities.

---

## Security & End-to-End Encryption Architecture

SAIRO uses the browser's native **Web Crypto API** so neither the Express server nor MongoDB ever sees your plaintext messages or your secret passcode:

1. **Zero-Knowledge Room Lookup (`PBKDF2-SHA256`)**
   - From the user's secret passcode, the browser derives a domain-separated lookup hash (`roomHash`) and an authentication verifier (`authVerifier = SHA-256("SAIRO::AUTH_VERIFIER::v1::" + roomHash)`).
   - The server verifies passcode knowledge using constant-time comparison (`crypto.timingSafeEqual`) without ever receiving the raw passcode.
2. **Independent Client-Side Encryption Key (`AES-256-GCM`)**
   - Each room stores a random 128-bit `salt` generated by the room creator's browser.
   - All participants derive a **non-extractable** `AES-256-GCM` `CryptoKey` locally via `PBKDF2-SHA256` (180,000 iterations) over `(passcode, roomSalt)`.
   - Even if the server database is leaked, ciphertexts cannot be decrypted without the original secret passcode.
3. **Per-Message 96-bit IV & Encrypted Metadata**
   - Every message (including text, optional reply quote, and the sender's temporary anonymous alias) is encrypted with a fresh random 96-bit initialization vector (`iv`).
   - Toggle **Inspect Cipher** inside any chat room to view the live AES-256-GCM ciphertexts stored in the backend.
4. **Auto-Vanishing Rooms (MongoDB TTL)**
   - Both `Room` and `Message` Mongoose schemas use MongoDB TTL indexes (`expiresAt`) to automatically purge expired rooms and encrypted messages.
   - Participants can also enable **Dissolve when empty** or click the **Flame (Burn)** icon to wipe the room immediately.

## Getting Started

### 1. Install Dependencies

```bash
npm run install:all
```

### 2. Configure MongoDB

Update `server/.env` with your local MongoDB or MongoDB Atlas URI:

```env
PORT=5000
MONGODB_URI=mongodb://127.0.0.1:27017/sairo_e2ee_chat
CLIENT_ORIGIN=http://localhost:5173
```

> **Note:** If MongoDB is not running locally during quick testing, the server gracefully falls back to an ephemeral in-memory store with identical TTL behavior and logs instructions in the console.

### 3. Run the Application

```bash
npm run dev
```

- **Frontend (React + Vite):** `http://localhost:5173`
- **Backend (Express + Socket.IO):** `http://localhost:5000`

### 4. Test Two-User Encrypted Flow

1. Open `http://localhost:5173` in Browser Window A, click **Create Room**, generate or type a secret passcode (e.g., `cedar-lotus-8492`), and enter the room.
2. Open `http://localhost:5173` in Browser Window B (or an Incognito window), click **Join with Code**, and enter the exact same secret passcode (or open the copied **Direct Room Link** and unlock it with the passcode).
3. Send messages back and forth and click **Inspect Cipher** or the **E2EE Shield** to verify the shared safety fingerprint and raw AES-256-GCM ciphertexts!
